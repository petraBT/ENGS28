    Section 7.2 Timer Interrupts

    When the timer’s update event fires, it can trigger an interrupt. The flow is:
    🔗
    1. Timer counts to ARR and generates an update event.
      🔗
    2. The timer sets its update interrupt flag (TIMx->SR bit UIF).
      🔗
    3. The Nested Vectored Interrupt Controller (NVIC) detects the flag and interrupts the CPU.
      🔗
    4. The CPU finishes its current instruction, saves context, and jumps to the Interrupt Service Routine (ISR).
      🔗
    5. The ISR clears the flag and does work.
      🔗
    6. The ISR returns; the CPU restores context and continues the main program.
      🔗
    Setting up a timer interrupt requires enabling the timer update interrupt in both the timer (TIMx->DIER UIE bit) and the NVIC (NVIC_EnableIRQ(TIMx_IRQn)).
    🔗

    Warning 7.2.2. Always Clear the Interrupt Flag.

    If you forget TIM3->SR &= ~TIM_SR_UIF; inside the ISR, the flag stays set and the ISR will be called again immediately after returning—the CPU will never get back to main().
